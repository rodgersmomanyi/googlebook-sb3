## 5. Recommended removals from the native module set (no kernel rebuild needed)
#  - thermal.ko (CONFIG_ACPI_THERMAL): useless on the SB3. The only ThermalZone in the firmware is \TPOL
#    (_HID MSHW0187, "Surface Thermal Policy") and it has no _TMP, so acpi_thermal_add() fails for it
#    (verified in the dumped DSDT, acpi/DSDT.dsl). Harmless if kept.

## 6. Config deliberately NOT added (evidence in STATUS.md)
#  UCSI_ACPI (lapis ships ucsi_acpi.ko; the SB3 \_SB.UBTC USBC000 device returns _STA=0 unless NVS USTC=1 and Windows
#    does not enumerate it), TYPEC_MUX_INTEL_PMC, INTEL_HID_EVENT / INTEL_VBTN (no INT33D5/INT33D6 in the tables),
#    ACPI_TAD (Android alarms use rtc0 = rtc_cmos, built in), ACPI_PROCESSOR_AGGREGATOR (\_SB.PAGD has a static _PUR and
#    is never notified), X86_MSR (gb_hw.sh uses lapis's vendor msr.ko), SURFACE_ACPI_NOTIFY (no MSHW0091 on the SB3),
#    SURFACE_PRO3_BUTTON / SURFACE_KBD (wrong devices), SENSORS_SURFACE_TEMP/FAN (need HWMON, which GKI x86 has off,
#    and the SB3 SAM node group has no sensor/fan nodes), MISC_RTSX_USB / MMC_REALTEK_USB (only if the base SD reader
#    turns out to be a Realtek vendor-class 0BDA:0129/0139/0179 device - see STATUS.md, SD card row).
