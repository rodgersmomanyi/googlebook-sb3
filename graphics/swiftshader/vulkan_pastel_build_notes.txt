SwiftShader -> vulkan.pastel.so  (Android x86_64 hwvulkan HAL)  build notes
===========================================================================
Date:        2026-10-21
Builder:     Ubuntu VM, 3 cores. SwiftShader HEAD cddb5c91b, NDK r27c.
Toolchain:   /build/ndk/build/cmake/android.toolchain.cmake (clang 18, lld)
Output:      /build/vulkan.pastel.so            (linked, unstripped, ~31 MB)
             /build/vulkan.pastel.stripped.so   (llvm-strip --strip-all, ~23 MB)
Both: x86_64 ELF shared object, SONAME=vulkan.pastel.so, HMI exported.

CONFIGURE / BUILD COMMAND
-------------------------
  cmake -S /build/swiftshader -B /build/swiftshader/build-x64 -G Ninja \
    -DCMAKE_TOOLCHAIN_FILE=/build/ndk/build/cmake/android.toolchain.cmake \
    -DANDROID_ABI=x86_64 -DANDROID_PLATFORM=30 \
    -DSWIFTSHADER_BUILD_TESTS=OFF -DCMAKE_BUILD_TYPE=Release
  ninja -C /build/swiftshader/build-x64 vk_swiftshader
  cp build-x64/libvk_swiftshader.so /build/vulkan.pastel.so
  patchelf --set-soname vulkan.pastel.so /build/vulkan.pastel.so
       # CMake forces soname=libvk_swiftshader.so and overrides -Wl,-soname,
       # so the soname is set after linking with patchelf.

          target_link_options(vk_swiftshader PRIVATE
              "-L/mnt/laps/system/lib64" "-Wl,--allow-shlib-undefined"

          target_link_libraries(vk_swiftshader PRIVATE log nativewindow sync)

    cutils/utils/base/hidlbase are NOT linked: with no HAVE_GRALLOC* and a static
    libc++, nothing references them (verified via nm -D -u).

RESULT (readelf -d / nm -D on /build/vulkan.pastel.so)
------------------------------------------------------
  HMI exported:  nm -D vulkan.pastel.so | grep -w HMI  ->  D HMI
  Exported dynamic symbols (exactly 4, per android_vk_swiftshader.lds):
      HMI, vk_icdGetInstanceProcAddr, vk_icdGetPhysicalDeviceProcAddr,
      vk_icdNegotiateLoaderICDInterfaceVersion
  SONAME:  vulkan.pastel.so
  NEEDED:  liblog.so  libnativewindow.so  libsync.so  libm.so  libdl.so  libc.so
      (libc++ is statically linked, so there is no libc++_shared dependency and
       zero std:: symbols are undefined. No cutils/utils/base/hidlbase/mapper deps.)
  The target device must provide at runtime, reachable from the HAL search path:
      liblog.so, libnativewindow.so (must export the VNDK AHardwareBuffer_* and
      AHardwareBuffer_getNativeHandle/createFromHandle), libsync.so (sync_wait),
      plus the standard libm/libdl/libc. All present on a normal Android image.
  One weak-undefined symbol remains (_ZTH... rr::Variable TLS init wrapper); weak
  undefined never blocks dlopen and the TLS var itself is defined in .bss.
